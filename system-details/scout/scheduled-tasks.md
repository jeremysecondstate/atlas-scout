# Scout: Scheduled-task responsibilities

Operating policy updated October 13, 2026. These are the current responsibilities to place in Scout's existing native tasks. Saved IDs, timing, enabled states, notification preferences and task memory remain local. This document does not invent a new schedule or claim a new native readback.

## Current responsibilities

| Existing task family | Current instruction |
| --- | --- |
| DATASTORE CATCH-UP | Complete local data preparation for the actual intended session; retain valid completed work and recover genuine failures. |
| GAMEPLAN STATS | Produce the normal local Gameplan evaluation/Stats work from actual saved observations. |
| MODEL REVIEW / TRAINING / PREDICTING | Complete the assigned normal numerical/model work under standing nightly authority; do not request another approval merely to continue preparation. |
| Local GAMEPLAN | Produce Scout's Gameplan research contribution for the intended action date. |
| GAMEPLAN SYNTHESIS / HANDOFF | Synthesize Atlas and Scout Gameplans with the available saved cash/share basis and deliver the result to Atlas; delivery completes the handoff without another snapshot, cross-trader state or acceptance. |
| DUCKETZ DISPLAY / OUTCOME REPORTING | Display available completed output and report actual faults; display/reporting is not a new approval or synthesis gate. |
| Local 15-minute preparation | Prepare Scout's own saved independent 15-minute binding each night. Never make this result a Gameplan prerequisite. |
| REPO RECONCILIATION / SOURCE COURIER | Preserve source ownership, exact-byte review/tests, durable queues and publication identities separately from nightly trading preparation. |
| Trader representative, if locally enabled | Observe the relevant trader's own saved activity; do not combine trader health or operate another trader. |

No task may require a human approval, verification ceremony, another trader's liveness, a shared ledger, a VPN/LAN/private gateway or a reciprocal acknowledgment before the authorized nightly workflow continues. Real inputs and truthful outcomes remain necessary for the calculation itself; report an actual failure and pursue its authorized correction.

## Timing and manual control

Use the existing registered recurrences and the actual intended action date in America/Los_Angeles. Retain the existing native dispatcher/watchdog and duplicate-work protections. A missed wake resumes eligible unfinished work; it does not authorize duplicate workers or fabricated timestamps.

Keep the established 03:00/03:35 outcome-notification checkpoints as reporting only. They do not create a new planning deadline or permission stage. The normal nightly preparation gets Gameplan and the local 15-minute trader ready for Jeremy's manual starts. Scheduled work does not enable trading or start/restart a trader.

Hyperliquid, Loop C review, legacy paused definitions and completed-chat cleanup keep their separately established responsibilities. Do not use this documentation revision to activate an unrelated task or overwrite a private native definition.
