# Nightly outcome notifications

This runbook follows the [permanent independent-trader policy](../independent-traders.md). The existing local nightly/display responsibilities report meaningful results and failures. Notification generation, delivery acknowledgment and peer readback never gate Gameplan preparation, synthesis, publication or a local 15-minute preparation result.

## What to report

Report completed combined Gameplan publication, a concrete failed operation, a meaningful recovery, or something that actually needs the human's attention. Name the intended action date, actual observed time, owner, failed operation and next action. Describe Gameplan, Atlas 15-minute and Scout 15-minute outcomes separately; one trader's condition is not another trader's readiness requirement.

Use existing wake times and notification preferences. The established 03:00 Pacific readiness-risk and 03:35 missing-result checkpoints are reporting times, not deadlines that prohibit authorized late completion. Use America/Los_Angeles with daylight-saving behavior. Report missing calculation inputs or failed work honestly without inventing a new approval or verification stage.

## Avoid duplicate messages

Reuse the same dated event identity and existing issue for the same unchanged condition. Retain the local read cursor and original notice evidence. A later native readback may establish whether a message was visible; unknown delivery remains unknown. It never holds up computation or publication. Do not keep emitting acknowledgments or repeat an unchanged non-actionable status.

The retained `tools.nightly_notifications` ledger may record dated notice claims/delivery if the local responsibility already uses it. Its `confirmed` field describes the actual requested result being available, not reciprocal approval or another trader's health. Do not supply invented proof to clear a notification record. Preserve old event/token/thread bindings privately.

## Native chat and privacy behavior

During a scheduled model wake, complete the assigned work, save the actual outcome and return the normal native final. Do not directly edit native chat databases or self-archive to suppress a result. The already installed separate completed-chat cleanup mechanism retains its own existing scope and receipts; notification reporting does not change it.

Use `atlas-scout` GitHub for sanitized substantive coordination. Keep financial packages in the existing private CODEXSTORE exchange. Do not publish account state, private logs, task memory, exact native IDs or tokens. Notification inspection does not call brokers/providers, train, start a trader or change controls.

Its historical readiness/acceptance wording does not add current operating gates.
